## R8-04 — P2 — некорректная структура JSON-ответа выходит из Promise и завершает процесс

**Где:** [pushNotificationService.js:59](/Users/vadimfertik/Desktop/reh_app-review/rehearsal-calendar-native/server/services/notifications/pushNotificationService.js:59), обращения к структуре ответа — строки 67–72.

**Клетка: особое стечение × серьёзно. Покрытие правкой причины: нет, регресс внесён заменой транспорта.** Нужен нештатный ответ внешнего сервиса; его появление у настоящего Expo не измерялось. Но цена — завершение серверного процесса и срыв обработки других напоминаний, а для обычного серверного runtime также остальных обслуживаемых им запросов. Исправление локальное, ориентировочно до часа, поэтому по HANDOFF выше планки. Это надёжность обработки внешнего отказа.

`try/catch` защищает только `JSON.parse`. После успешного разбора `200 null` чтение `result.errors` бросает `TypeError`; при `503 {"errors":"temporarily unavailable"}` бросает `.map`. Код выполняется в обработчике `IncomingMessage` → `end`, уже вне синхронного выполнения конструктора Promise. Исключение не попадает ни в `reject`, ни в `try/catch` отправки/планировщика. В самостоятельном процессе Node 22.16 получен **exit 1**, вызывающий `catch` не выполнен. То же происходит на пути квитанций.

На `bb3d96f` те же три ответа отклоняют Promise, вызывающий `catch` выполняется, процесс завершается штатно (**exit 0**). Таким образом, это измеренный регресс перехода с `async fetch` на callback API. Обещание «сбой отправки становится результатом/ошибкой прогона» для этой ветки нарушено; гарантия ограничения времени ожидания сама по себе сохранилась.

**Минимальное воспроизведение** из `rehearsal-calendar-native/server`, Node 22, только loopback; `.env` и база не нужны:

```js
import http from 'node:http';
import { expoTransport } from './services/notifications/pushNotificationService.js';

const server = http.createServer((req, res) => {
  req.resume();
  req.on('end', () => {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end('null');
  });
});
await new Promise(resolve => server.listen(0, '127.0.0.1', resolve));
try {
  await expoTransport({
    baseUrl: `http://127.0.0.1:${server.address().port}`, timeoutMs: 350,
  }).sendPushNotificationsAsync([{ to: 'ExponentPushToken[review]', title: 'review' }]);
} catch (error) {
  console.log('caught by caller', error.message); // на HEAD не достигается
} finally {
  server.closeAllConnections();
  server.close();
}
```

Для второго варианта заменить ответ на статус 503 и `{"errors":"temporarily unavailable"}`. Для квитанций вызвать `getPushNotificationReceiptsAsync(['review-ticket'])` при `200 null`.

**Исправление причины:** общий разбор ответа в `post` должен проверять форму envelope и направлять любое исключение разбора/валидации в `settle(error)`. Это одна граница для отправки и квитанций. Регресс-тест должен требовать перехватываемый отказ и живой процесс для этих ответов. Штатные 18 мутаций проверяют прежние механизмы и данную ветку не покрывают.

### R8-04 — закрыто

**Клетка прежнего замечания: особое стечение × серьёзно. Покрытие правкой причины: полное для выхода исключения из обработчика ответа.**
