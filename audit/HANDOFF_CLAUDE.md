## 4. Метод: облегчённый, качество то же

**Как чиним: причину, а не симптом (решение владельца 26.09).** «Я не хочу
заплатки ставить, нужно чинить чтоб не возвращаться к этому в будущем, если
возрастёт трафик, юзеры, фичи». Это значит:
- правило живёт в одном месте для всех, кто им пользуется;
- инвариант записан в схеме или контракте;
- на каждый класс ошибок — один механизм.

Находку, которую закрывает правка причины, закрываем этой правкой, даже если
сама по себе она ниже планки. Если инвариант делает гонку невозможной по
построению (ограничение в схеме, ключ), отдельная проверка на гонку не нужна.

**Планка — где остановиться (решение владельца 26.09):** «мне важно, чтоб
аппка работала без сбоев, но нагружать супер безопасностью или сценариями 1 на
миллион не стоит». Планка решает только то, что правка причины не закрывает:
новые сценарии, которые находит ревьюер, и экзотику, которой нужен отдельный
механизм. Каждой такой находке два вопроса: как срабатывает и чего стоит.

| | Мелко: повторить, перезайти, обновить; задело только того, кто сделал; косметика | Серьёзно: чужие данные или аккаунт, потеря данных без возврата, сломано у других |
|---|---|---|
| **Просто**: само при обычном использовании или простым способом (другой id в запросе, регистрация на чужую почту) | чинить | чинить первым |
| **Особое стечение**: попасть в доли секунды, уже иметь чужой телефон, сессию или пароль, доступ к серверу | строка в `docs/known-issues.md` | чинить, если дёшево (около часа); иначе — вопрос владельцу |

Клетку называть одной строкой в ответе на замечание. Владелец смотрит только
серую — особое, серьёзное и дорогое.

**Не меняется — это и есть качество:**

- воспроизведение до правки: тест красный до, зелёный после;
- мутационная проверка для серверных охранных механизмов (доступ, сессии,
  данные): вернуть баг и увидеть, что его ловят. Клиент и экраны — обычный
  тест, красный до правки, без мутационных скриптов (с 26.09);
- серверное — на настоящем PostgreSQL;
- честные статусы: `NOT_RUN`, `READY_FOR_CHECK`, `BLOCKED`; VERIFIED — только по
  критериям плана.

**Облегчено (замерено 22.09):**

- Jest всегда с `--silent`. Полный прогон без него — 742 КБ вывода (~190 тыс.
  токенов), с ним — 7 КБ при том же итоге. В 15 сохранённых логах агента —
  около 3,2 млн токенов шума.
- Длинный вывод — в файл доказательств; в контекст только `tail` и строки
  `Tests:` / `FAIL`.
- Полный `npm run check` — один раз в конце пакета. Внутри — адресные тесты.
- Один отчёт на пакет (`audit/REMEDIATION_R2.md` и дальше): таблица ID → коммит →
  тест → результат, проза только для нестандартного. Один `manifest.json` на
  пакет в `audit/evidence/<пакет>/`: sourceCommit, sourceTree, sha256 изменённых
  файлов и логов.
- Объём проверок по важности: High — всё; Medium — воспроизведение и
  регресс-тест; Low — регресс-тест.
- Без субагентов и параллельных веток работы, если владелец не просит.
  Независимую проверку делает Codex.
- Коммит на каждую проверенную находку — обрыв сессии тогда ничего не стоит.

## 5. Среда и грабли

- **Node 22.16.0** (`.nvmrc`):
  `export PATH="$HOME/.nvm/versions/node/v22.16.0/bin:$PATH"`. На Node 20
  нативный `better-sqlite3` падает с `NODE_MODULE_VERSION` — это среда, не регресс.
- **`server/.env` — production**: там боевой `DATABASE_URL` Neon. Рантайм его сам
  не грузит; не подставляй его и через `SERVER_ENV_FILE`. Для PostgreSQL —
  Docker-харнесс: `npm --prefix rehearsal-calendar-native/server run test:r0-postgres`
  (Docker должен быть запущен).
- **Команды.** Из `rehearsal-calendar-native`: `npm test` — Jest и браузерные
  тесты; `npm run check` — секреты, типы, тесты. Адресно:
  `NODE_OPTIONS=--experimental-vm-modules npx jest <шаблон> --silent`. Из
  `server`: `npm run test:unit` — только Jest, быстро.
- **CLAUDE.md местами устарел, этим местам не верь:** «650 tests across 47 suites»
  (сейчас около 1270 в 88); раздел напоминаний — оба крона выключены с 12.09, а
  «a failed push releases the claim» неверно (GR01); «Transactions table» в
  админке — платежей нет; «Node.js 18+» — закреплён 22.16.0. Раздел про мигратор
  (`--fresh`, `--adopt`, отказ от `--baseline`) пришёл вместе с WIP: описание
  опережает проверенный код, считай его утверждением, которое надо доказать.
