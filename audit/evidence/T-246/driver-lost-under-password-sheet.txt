T-246 - "Screen headers, one style" and the 20 flows after it, full e2e on
auto/main 3b38601, 11.11.2026. Why they failed, and the fix.

1. The red run (rehearsal-calendar-native/e2e/out/failed/
   full-e2e-3b38601-2026-11-11T09-01-37-616Z): flows 01..65 passed; 66 and every
   flow after it failed. junit.xml: 20 x

     maestro.DeviceUnreachableException: Device became unreachable during deviceInfo

   and "Unknown error" (251 ms) for the 21st (70, privacy). No assertion of any
   flow failed. "taps taken again (tap-and-see.yaml): 0" - not a lost tap
   (T-207), so not the tap-and-see exception.

2. Flow 66's maestro.log ends inside sign-in-submit.yaml, right after the tap
   on "Not Now" of iOS's "Save Password?" sheet:

     10:57:26.163 Tapping on element ... accessibilityText=Not Now
     10:57:27.348 Tap on "${TAP}" COMPLETED
     10:57:27.385 Assert that (Optional) "${GONE}" is not visible RUNNING
     (nothing after)

3. The driver's own log (device-xctest.log) at that moment:

     22:57:27.533 [ViewHierarchyHandler] Fetch status bar hierarchy - start
       t = 5577.12s Get all elements bound by index for: Descendants matching type StatusBar
     <unknown>:0: error: -[maestro_driver_iosUITests testHttpServer] : Failed to

       element <AXUIElementRef> {pid=58171} ...)
       t = 5577.28s Tear Down
     Test Case '-[maestro_driver_iosUITests testHttpServer]' failed (5577.280 seconds).

   Maestro's iOS driver is one long XCTest test; an XCTest query failure ends
   it, and every later request finds no driver.

4. pid 58171 is InputUI (device-simulator.log: "localhost InputUI[58171]"), the
   process that draws the "Save Password?" sheet. In the same 30 ms SpringBoard
   reports it in the status-bar query and takes its scene down:

     10:57:27.556 SpringBoard: Element RemotePlaceholder, pid: 58171 ... is remote hosted
     10:57:27.559 Found remote element in snapshot tree: RemotePlaceholder, pid: 58171
     10:57:27.561 runningboardd: Invalidating assertion ... target:[osservice<com.apple.InputUI>:58171]
     10:57:27.562 SpringBoard: [osservice<com.apple.InputUI>:58171] Setting process visibility to: Background
     10:57:27.565 SpringBoard: com.apple.InputUI(58171) lostConnection (invalidation)

   The sheet's window went away while the driver read it: the cause is the
   sheet, shown at every sign-in (some 90 a run), not flow 66 or its screen.
   Rare (one driver end in the full runs kept in e2e/out/failed since 01.11),
   so it cannot be had on demand; the log is the proof for it.

5. Fix: e2e/run.mjs turns AutoFill Passwords off on the e2e simulator at boot
   (defaults write com.apple.WebUI AutoFillPasswords -bool false); iOS then
   offers nothing and there is no InputUI sheet to go. sign-in-submit.yaml no
   longer waits for it; flow 01 waits 5 s for "Not Now" and asserts it is not
   there.
