These two old, unchanged tests depend on `ps`, which this session's sandbox
denies (startedAt() returns ""): their groups are bare /bin/sleep with no
watchdog, so without ps nothing can identify or end them. The first failed
here before this change too (lock-tests.txt). The second used to pass here
because the old clearLeftovers took the lock after 15 s with the group still
running. That is exactly what round 2 asks it not to do: without ps it now
refuses the lock. Where ps runs (the supervisor's npm test), the first group's
start time matches and it is stopped, and the second's does not match and it
is left alone, as before.
