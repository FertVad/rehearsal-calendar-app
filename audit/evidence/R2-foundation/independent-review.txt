   permanent observer on pool connect closes that gap. An actual owned socket
   failure on nextTick during acquire is observed; the failed client is discarded
   and a later query obtains a healthy backend. Release-once behavior is separately
   tested with an owned backend terminated while its transaction is between queries.
2. Affected counts: requested complete ordinary/scoped 0/1/N coverage, not a mixture
   split between modes. The final contract asserts each mode, scoped lastInsertId,
   and conflict/no-op zero counts against real committed PostgreSQL rows.
3. Closing with pending acquisition: requested a real waiter remain queued after
   ten holders finish before the two-second deadline. The final test proves close
   remains pending until refusal, then queue/client counts reach zero and the
   sentinel INSERT never occurs.
4. Configured connection failure: added an absent synthetic database on the same
   owned endpoint. A real driver attempt fails, leaves no published adapter or
   SQLite file, drains the failed candidate, and the next explicit good init works.
5. Probe evidence: the pre-query lease barrier proves an init/close publication
   race, not an in-flight read timeout. A separate final test pauses an authenticated
   socket's reads without faking query results. Independent pg_stat_activity sees
   the actual SELECT1 execute; the two-second read timeout rejects initialization
   and destroys the candidate socket before the next healthy init.
6. Engine identity during drain: the adapter author identified that immediately
   setting isPostgres=false could switch an issued service transaction's SQL dialect
   between awaits. Independently reviewed the fix retaining true until drain ends.
   A real scoped current_database query after close starts proves the retained
   PostgreSQL path; the flag becomes false after close completion.
7. req.db attachment: both root and this reviewer found that a value snapshot before
   lazy initialization left first requests with undefined or later stale handles.
   Root replaced it with a live getter. Existing routes used live imports; the
   compatibility fix does not initiate a connection merely by reading the property.
8. Copied-entrypoint ownership: requested IPC-disconnect cleanup so a child listener
   cannot outlive its parent. The final helper has a disconnect exit, unref'ed IPC,
   SIGTERM with a bounded SIGKILL fallback, and a real disconnect regression. Cleanup
   observes process exit and stdout/stderr completion before boundary/log checks.

Adapter correctness and boundaries
Transactions own one client for BEGIN/callback/COMMIT or rollback, expire captured
scoped handles, discard failed rollback connections, and reject PostgreSQL's
COMMIT-to-ROLLBACK response when a callback swallows a statement error. run exposes
driver rowCount alongside lastInsertId. Existing placeholder conversion and implicit
INSERT RETURNING compatibility are retained, not redesigned here.

The actual locked pg-pool queue removes timed-out waiters; it is not a wrapper
Promise.race that leaves late SQL queued. Pool max10, queue cap100 and separate
acquisition/probe deadlines are tested. Probe client read timeout means discard,
not a claim that arbitrary server SQL was cancelled. Business SQL retains operation
policies such as IS02's scoped limits; there is no blanket business-query deadline.
Graceful close drains issued leases/callbacks. An indefinitely suspended callback
may still keep it pending; no forced cancellation or hard shutdown bound is claimed.

Startup and configuration
Public documents, associations, invite fallback, admin HTML/assets and liveness do
not initialize PostgreSQL. The runtime shares one attempt per app instance and
caches an init failure instead of reconnecting on every request. The new readiness
route explicitly probes connectivity and uses no-store; it is not a schema proof,
cached live guarantee or added timer. Documentation states a probe can incur compute.

SERVER_ENV_FILE is explicit and absolute, evaluated before configuration consumers;
default startup does not discover .env. External process values retain precedence.
Security configuration remains fail-fast. A direct non-VERCEL invocation owns its
listener; imported/Vercel handlers default-export the app without starting one.
Existing Vercel build/routes/public inclusion and disabled branch deployment remain
intact. A copied local handler fixture is not a deployment packaging/smoke test.
