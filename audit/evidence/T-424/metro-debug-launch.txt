 WARN  [WARN] [Attribution] the install conversion value was not taken: {"code": "attribution", "message": "The operation couldn’t be completed. (SKANErrorDomain error 10.)", "name": "Error", "stack": "Error: The operation couldn’t be completed. (SKANErrorDomain error 10.)"}

Reading: that warning is printed only in the catch of registerInstall(), after
NativeModules.RehearslyAttribution.install was found as a function and called.
The rejection's code "attribution" is the one RehearslyAttribution.m passes to
reject(); the NSError inside is SKANErrorDomain — StoreKit's SKAdNetwork
answered the call. So under newArchEnabled the RCT_EXPORT_MODULE module is
available through the interop layer and the call reaches SKAdNetwork; no
move to Expo Modules API / TurboModule is needed. The simulator refuses the
value (the task: success or error equally show the call got there).

With round 1's change (attribution.ts), a missing module would print instead:
 WARN  [WARN] [Attribution] the native module RehearslyAttribution is missing; no install postback
and a taken value:
 LOG  [DEBUG] [Attribution] the install conversion value was taken
