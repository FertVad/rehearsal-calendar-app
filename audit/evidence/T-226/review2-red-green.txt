T-226 review, second round (Астра) — red before and green after:
a stop before midnight after a failed batch
=================================================================

The finding against b1e2692: run.mjs's loop sets process.exitCode = 1 when a
batch fails; if nextStep then returns { stop }, it throws EnvironmentError, and
main().catch sets `machine ? 75 : 1` — 75 over the 1. The supervisor takes the
run as the machine's: no red result kept, no flake registered.

The fix: the run's exit code is exitCode({ failed, error }) in e2e/midnight.mjs;
a stop for the machine after a failed batch is 1, 75 only when nothing failed.
run.mjs says "stopped, a flow had already failed (junit.xml): midnight in …"
instead of "not ready, not the change". junit.xml is written after each batch
and the artifacts flattened as before; the wait, batches and reseed unchanged.

Red: exitCode put back to what b1e2692's handler did
(`if (error === 'machine') return 75;` — 75 whatever had failed).
The test plays the review's path: two flows from 23:50, setup 3 min 39 s; the
first a batch of its own (take 1), failed after 54 s + 134 s; then nextStep
gives stop (wait past the 900 s limit).
