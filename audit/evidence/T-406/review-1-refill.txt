The cause: layOut with refill set `laid` to null, so the move branch (user.days !== key) never ran;
new days were added, weekends_days was overwritten, and the old weekday rows stayed.

The fix: layOut with refill first deletes the defaults from today on
(deleteWeekendDefaults(tx, userId, { from: today })), then lays out the zone's weekend — "on" always
means the weekends of the current zone. Same transaction, same row lock; the person's own marks and
past days are not touched (deletion is by source 'weekend' and date >= today).
