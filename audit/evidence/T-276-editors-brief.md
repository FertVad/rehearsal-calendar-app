# T-276 — задание редакторам-носителям (ru / es / de; en — для полноты)

Вычитка по процедуре T-256: каждый язык читает свой редактор-носитель, ответ —
отдельный файл `T-276-natives-<язык>.md` с вердиктом по каждой строке
(«оставить» или «заменить на …» и почему). До этих ответов пункт 4 задачи
не выполнен: прочтение в `T-276-calendar-event-language.txt`, раздел 3, —
собственное прочтение Claude, не редактора.

## Где видно

Календарь iPhone (приложение «Календарь»), событие, которое Rehearsly
выгружает туда за человека. Видны две вещи:
- **название события** — в списке дня, в виджете, в уведомлении календаря;
  длинное обрезается справа;
- **заметки** — в карточке события, внизу.

Если у репетиции есть своё название от организатора (например, «Прогон»),
названием события будет оно, без перевода; строка ниже — только для
репетиции без названия. `<проект>` — название проекта, как его ввёл человек,
на любом языке и в любом алфавите.

Слово для репетиции взято из интерфейса этого языка (`calendar.rehearsal`):
Репетиция / Rehearsal / Ensayo / Probe.

## Строки (`rehearsal-calendar-native/src/i18n/translations/calendarSync.ts`)

| Язык | Название (`eventTitle`) | Заметки (`eventNotes`, пустая строка между ними) |
|---|---|---|
| ru | Репетиция: Гамлет | Проект: Гамлет / Создано в Rehearsly |
| en | Rehearsal: Hamlet | Project: Hamlet / Created via Rehearsly |
| es | Ensayo: Hamlet | Proyecto: Hamlet / Creado con Rehearsly |

## Вопросы редактору

1. Звучит ли название так, как носитель назвал бы событие в своём календаре?
   Двоеточие и порядок «Слово: проект» — естественны или лучше иначе?
2. Нужны ли кавычки вокруг названия проекта (в пушах проект в кавычках: «X»,
   „X“), или в календаре без них лучше?
3. «Создано в / Creado con / Erstellt mit Rehearsly» — естественная подпись
   приложения? Вариант лучше?
4. Для es: одинаково ли читается в Испании и Латинской Америке.

Ограничение: английская форма (`Rehearsal: <проект>`, `Created via Rehearsly`)
остаётся в распознавании старых событий в любом случае — правка ru/es/de его
не затрагивает. Новая формулировка любого языка требует только поправить
строку словаря и ожидание в `exportLanguage.test.ts`.
