# Правила работы с репозиторием

## Production — обязательная граница

Инструкция Вадима от 18 сентября 2026. Подробности и карточки человека:
[audit/PRODUCTION_ACCESS.md](audit/PRODUCTION_ACCESS.md).

- `rehearsal-calendar-native/server/.env` содержит **боевой DATABASE_URL**. Не использовать его в тестах и не считать локальный запуск сервера безопасным. Для проверок использовать `createApp` и изолированные fixtures/одноразовый PostgreSQL без загрузки `.env` или production entrypoint `server.js`.
- До любого обращения к `rehearsly.me`, боевой БД, фактической production schema/migration ledger или переменным Vercel **остановиться и сообщить отдельной строкой**: «Нужен production: <конкретное действие>. Ожидаю решения Вадима». До решения действие не выполнять.
- То же правило действует для deployment smoke, push ветки и первого удалённого запуска workflow `Application checks`. Локальный commit и изолированные проверки не являются push/deploy.
- По сообщению Вадима Neon исчерпал compute quota и отвечает SQLSTATE `53000`; production endpoints возвращают `FUNCTION_INVOCATION_FAILED`. Не перепроверять, не опрашивать, не обходить и не тратить время на повторную диагностику этого известного отказа. Он не доказывает регресс локальной ветки. Восстановление плана Neon — решение Вадима.
- Не добавлять scheduled polling/monitoring production. Даже read-only запрос может будить compute и расходовать квоту.
- Напоминания остаются выключенными: cron-job.org отключён человеком, GitHub reminder workflow отключён вручную, cron в файле закомментирован. Не включать, не запускать вручную в production и не создавать заменяющее расписание. Возврат — отдельное решение после R8.
- IA01: наличие непустого `APPLE_CLIENT_ID` в реальных переменных Vercel проверяет человек по карточке `OPS-IA01`. Локальная проверка guard не подтверждает deployment configuration.

## Порядок исправлений

Работать постепенно по [плану](audit/REMEDIATION_PLAN.md) и вести
[реестр](audit/REMEDIATION_STATUS.md), с отчётом после каждого пункта.
Evidence должен ссылаться на проверенный source commit; исторические манифесты
не переписывать под последующий HEAD без нового прогона.

### Продолжение без остановок — 18 сентября 2026

Вадим поручил двигаться по плану последовательно без ожидания нового
«продолжи» после каждого пункта. После каждого пункта сохранять отдельный
отчёт/evidence, сообщать результат и переходить к следующему. Разрешение на
push той же ветки `codex/systematic-repair` и её Application checks уже получено;
автодеплой ветки должен оставаться отключённым.

Когда понадобится production, отдельно обратиться к Вадиму по правилу выше
и остановить зависимые действия до его решения. Проверить актуальные публичные
тарифы Neon и рассчитать стоимость конкретной проверки/дальнейшей эксплуатации
с явными допущениями; не выдавать оценку за измеренный счёт аккаунта. Независимые
локальные работы можно продолжать. Это поручение не разрешает production-доступ,
deploy, оплату, миграции или включение напоминаний.
