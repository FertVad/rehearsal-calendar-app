# Релиз в App Store — пошаговый план

Рабочий runbook для выката Rehearsly в App Store. Отмечай галочками по ходу.

**Состояние на момент написания:** managed workflow (Expo SDK 54), папка `ios/`
гитигнорится и генерируется через `prebuild`. Bundle ID `com.rehearsal.app`,
EAS `projectId` прописан. Платежи намеренно выключены — в приложении нет ни
одного элемента покупки.

| 0.2 | Убрать `<BetaBanner />` и его импорт | `src/navigation/index.tsx:14,176` | ❌ |

| 0.5 | **Sign in with Apple** — обязателен по Guideline 4.8 | `LoginScreen.tsx`, `appleAuth.ts` | ✅ сделано |

**0.5 — почему это было блокером.** Guideline 4.8 требует равнозначный
приватный способ входа везде, где предлагается сторонний. На экране входа был
только Google — этого достаточно для отказа на ревью. Бэкенд был готов
(`apple-signin-auth`, `POST /auth/apple`, `loginWithApple`), не хватало нативной
части. Проверено на устройстве: вход связался с существующим аккаунтом по
совпадающей почте, добавив Apple вторым провайдером рядом с Google.

Из четырёх Apple-переменных нужна **только `APPLE_CLIENT_ID`** (= bundle ID):
`apple-signin-auth` сам тянет публичные ключи Apple. `APPLE_TEAM_ID`,
`APPLE_KEY_ID` и `APPLE_PRIVATE_KEY` нужны лишь для server-to-server обмена,
которого у нас нет.

**0.1 — конкретно.** Сейчас плагин лежит в `_disabled_plugins` с комментарием
про Personal Team. Платный аккаунт есть → перенести обратно:

```json
"plugins": [
  "expo-web-browser",
  ["expo-notifications", {
    "icon": "./assets/notification-icon.png",
    "color": "#A855F7"
  }]
]
```

После правки обязательно `npx expo prebuild --clean` — плагин прописывает
`aps-environment` в entitlements, без этого APNs не поднимется.

**0.4 — почему опционально.** Экран подписки не зарегистрирован в навигации,
premium-бейдж рендерится только при `status === 'active'`. Покупок нет → бейдж
не появится. Запрос просто впустую ходит на сервер при каждом открытии профиля.
На ревью не влияет.

### Грабли, на которые наступили

- **Xcode-проект называется `Rehearsly`**, а не `rehearsalcalendarnative` — `prebuild`
  берёт имя из `app.json`. Открывать нужно `ios/Rehearsly.xcworkspace`.
- **`DEVELOPMENT_TEAM` не проставляется автоматически** — после каждого
  `prebuild --clean` нужно заново выбрать Team в Signing & Capabilities.
- **`pod install` падает** с `Encoding::CompatibilityError`, если не задана
  UTF-8 локаль. Лечится `LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 pod install`.
- **Xcode просит «доверить сертификат» в VPN & Device Management**, хотя у платного
  аккаунта раздел пустой и доверять нечего. Сообщение ложное — если приложение
  установилось, его можно игнорировать.
- **`No script URL provided`** — сборка Debug и требует запущенного Metro
  (`npx expo start`). При запуске из Xcode он поднимается сам, при запуске
  через `devicectl` — нет.
- **Скрипты вне сервера должны звать `initDatabase()`** перед использованием `db` —
  модуль экспортирует живой биндинг, до инициализации `db.all` не существует.
- **Apple разрешает максимум 2 APNs-ключа на аккаунт** — оба слота заняты.
  Для третьего придётся отзывать старый.
- **Деплой Vercel падал на `CRON_SECRET`** с лишним пробелом/переносом строки
  (`openssl rand -base64 32` дописывает `\n`). Падало на этапе `vercel build`,
  до сборки кода, поэтому прод месяцами отдавал последнюю удачную сборку, а
  новые переменные окружения не подхватывались. Генерировать так:
  `openssl rand -base64 32 | tr -d '\n'`.
- **Порядок в `logout()` имел значение**: отзыв сессии (`/auth/logout` поднимает
  `token_version`) должен идти **после** отвязки push-токена, иначе `DELETE`
  уходит с уже недействительным токеном и получает 401, а токен остаётся в базе.

**Что уже готово и трогать не надо:** `expo-notifications@0.32.16`, `expo-device`,
серверный `expo-server-sdk@3.15.0`, `pushNotificationService.js` с рассылкой по
локали (ru/en/es/de), `notification-icon.png`, обработка сценариев — новая
репетиция, изменение, отмена, отклик, приглашение, смена роли, напоминания за
24 ч и 1 ч.

**Симулятор пуши не поддерживает** — только физическое устройство.

## Платежи — разбор

Это главный архитектурный вопрос, поэтому подробно.

### Короткий ответ

**Да, можно брать деньги только через AllPay на лендинге.** Подключать Apple IAP
не обязательно — при одном жёстком условии: **в приложении не должно быть ничего,
что ведёт к покупке.** Ни кнопки «Оформить подписку», ни цен, ни ссылки на сайт
с тарифами, ни даже текста «оформите подписку на rehearsly.com».

Так живут Notion, Slack, Figma, Linear — их iOS-приложения не продают ничего,
подписка покупается на сайте, приложение только логинит и показывает оплаченное.
Apple это разрешает.

### Почему нельзя просто оставить AllPay внутри приложения

Guideline 3.1.1 требует IAP за разблокировку функциональности. Подписка у нас
открывает создание проектов — это цифровой контент внутри приложения. Провести
такую оплату через сторонний процессинг = отказ на ревью. Именно поэтому просто
снять флаги `TEMPORARILY DISABLED FOR LAUNCH` и включить AllPay-чекаут в
приложении **нельзя**.

### Три варианта

**Вариант A. Только веб (AllPay на лендинге)** — рекомендую для старта

- Комиссия Apple: **0%**
- Переделывать в приложении: ничего. Просто не включать обратно экран подписки.
- Сделать на лендинге: секцию с тарифами (сейчас её нет вообще) и чекаут
- Backend: уже готов — вебхук, токенизация, рекуррентные списания работают
- Минус: хуже конверсия, пользователь уходит из приложения; нельзя даже намекнуть
  внутри, где платить
- Риск ревью: низкий, если в приложении реально ноль упоминаний покупки

**Вариант B. Apple IAP (StoreKit)**

- Комиссия: 15% по Small Business Program (до $1M/год), дальше 30%
- Переделывать: интеграция `react-native-iap` или `expo-in-app-purchases`,
  серверная валидация чеков, обработка App Store Server Notifications для
  продлений и отмен, новые продукты в App Store Connect
- AllPay при этом остаётся для веб-покупок — две параллельные системы, которые
  надо сводить в одной таблице подписок
- Оценка: 1–2 недели работы
- Плюс: покупка в один тап, лучшая конверсия, доверие пользователя

**Вариант C. Гибрид с внешней ссылкой (только US)**

После решения по делу Epic v. Apple (2025) Apple обязали разрешить приложениям
в **американском** сторфронте выводить ссылки на внешнюю оплату без комиссии и
без предупреждающих экранов. В остальных сторфронтах анти-стиринг остался.

Практически это значит: можно показывать ссылку на оплату на сайте, но только
пользователям из США, с гейтом по стране. Усложняет код, экономит комиссию
на одном рынке. Для нашего масштаба — избыточно.

### Что рекомендую

Релизить **1.0 бесплатным** (как и запланировано — все функции открыты) и
монетизацию не трогать. Экран подписки уже недостижим из навигации, покупок в
приложении нет, ревью пройдёт чисто.

Когда дойдёт до денег — **Вариант A**: добавить тарифы на лендинг, продавать
через AllPay, приложение оставить «только вход». Ноль комиссии, backend уже
написан и работает. Если упрётесь в конверсию — тогда считать, окупает ли
15% прирост от IAP.

### Важные оговорки

- Правила App Store меняются часто, а этот разбор сделан по состоянию на момент
  написания. **Перед подачей перечитай актуальные
  [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/),
  раздел 3.1.** Особенно если между написанием и подачей прошло несколько месяцев.
- Если приложение будет продаваться B2B (театрам как организациям, а не частным
  лицам) — стоит посмотреть Guideline 3.1.3(c) Enterprise Services, там правила мягче.
- Демо-аккаунт для ревьюера обязателен в любом варианте: без него ревьюер увидит
  экран логина и не сможет проверить приложение.

## Чеклист «включить платежи обратно»

Когда решишь монетизировать — **не просто снимай флаги**. Сначала выбери вариант
из разбора выше. Места с флагом `TEMPORARILY DISABLED FOR LAUNCH`:

1. `server/routes/native/projects.js:45` — вернуть `requireSubscription` в `router.post('/')`
2. `src/features/projects/screens/ProjectsScreen.tsx` — проверка подписки + Alert
3. `src/navigation/index.tsx` — проверка в `ActionSheetWrapper`
4. `src/features/calendar/hooks/useAddRehearsalForm.ts` — проверка в `handleCreateProject`
5. `src/features/profile/screens/ProfileScreen.tsx` — пункт меню «Подписка»

**Для Варианта A** (веб-оплата) включать нужно только пункт **1** — серверную
проверку. Пункты 2–5 добавляют в приложение UI покупки, что как раз нарушает
3.1.1. Вместо Alert со ссылкой на оплату показывай нейтральное «Для создания
проектов нужна подписка» без указания, где её взять.
