# Сервисы: что где живёт

Все внешние сервисы, от которых зависит Rehearsly, — зачем каждый нужен, какой
переменной подключается, во что упирается и что сломается, если отвалится.

Секретов здесь нет и быть не должно: только **имена** переменных. Значения — в
Vercel → Settings → Environment Variables и в локальном `server/.env`.

Runtime-раздел обновлён 2026-09-19 для ветки исправлений; это не подтверждение
состояния production. Остальные сервисные сведения исходно от 2026-09-12.

## База данных

### Neon — PostgreSQL

Боевая база. Четырнадцать таблиц с префиксом `native_*`.

| | |
|---|---|
| Переменная | `DATABASE_URL` (принимается и `POSTGRES_URL`) |
| Читается в | [PostgreSQL adapter](../server/database/db.js), [runtime](../server/runtime.js) |
| Если недоступна при инициализации | Зависимые API и `/api/ready` отвечают503; public HTML и `/api/health` продолжают работать при корректной security configuration. Исправление ещё не задеплоено. |

**Состояние на 2026-09-12: бесплатный лимит 100 CU-часов выбран полностью.**
Neon считает время, пока compute бодрствует, и усыпляет его примерно через пять
минут простоя. Пинг раз в 15 минут держал базу бодрствующей треть суток, а два
планировщика на этом интервале съедали весь месячный лимит — почти всегда чтобы
услышать «отправлять нечего». Оба выключены, см. раздел про напоминания.

**Локальное окружение:** `server/.env` содержит **боевой `DATABASE_URL`**.
Сервер ветки исправлений больше не читает этот файл автоматически: он использует
process environment либо явно выбранный абсолютный `SERVER_ENV_FILE`.
Для разработки нужен изолированный PostgreSQL; SQLite runtime и fallback удалены.
Публичные страницы не инициализируют БД. Первый зависимый запрос делает одну
общую попытку подключения; после отказа требуется restart или явное восстановление
adapter, автоматического повторения по трафику нет. Подробнее: [runtime](server-runtime.md).
Это изменение ещё не означает восстановления текущего production.

## Хостинг и домен

### Vercel

Express-сервер целиком: API, публичные страницы (лендинг, privacy, support) и
инвайт-ссылки `/invite/*`. Всё с одного origin — это требование, а не удобство:
`apple-app-site-association` обязан лежать на том же домене, что и ссылки, иначе
Universal Links не работают.

| | |
|---|---|
| Конфиг | [server/vercel.json](../server/vercel.json) |
| Переменные | `BASE_URL`, `NODE_ENV`, и все остальные из этого документа |
| План | Hobby |

**Две вещи, которые Hobby диктует архитектуре:**
- запись `crons` допускает **один запуск в сутки**, а более частая валит весь
  деплой ещё до сборки — поэтому триггер напоминаний живёт снаружи;
- функции не резидентны между запросами, поэтому внутрипроцессный планировщик
  (`node-cron`) там не работает в принципе.

**Грабли:** `includeFiles: "public/**"` в `vercel.json` обязателен —
`express.static` разрешает пути в рантайме, бандлер не догадается, что папка
нужна, и выкинет её.

### Домен `rehearsly.me`

Регистратор и где лежит DNS — *вписать сюда*. Через DNS завязаны три вещи:
MX-записи для входящей почты (ImprovMX), SPF и DKIM для исходящей (Resend), и
сам домен, на который смотрит Vercel.

## Напоминания о репетициях

`GET /api/cron/reminders` находит репетиции и рассылает пуши. Сам себя он
вызвать не может — нужен внешний триггер. Их было два.

> **Сейчас выключены оба. Напоминания не рассылаются ничем.**
> Причина — расход compute у Neon, см. выше.

| | |
|---|---|
| Переменная | `CRON_SECRET` (одно значение в Vercel и в секретах репозитория) |
| Читается в | [server/routes/cron.js](../server/routes/cron.js) |
| Без переменной | эндпоинт отвечает **503**, а не работает без авторизации |

### cron-job.org — основной, выключен 2026-09-12

Бесплатный, точный до минуты. **Не ходит по редиректам**, поэтому URL должен
быть ровно `https://rehearsly.me/api/cron/reminders` — без `http://` и без `www`.

### GitHub Actions — резервный, выключен 2026-09-12

[.github/workflows/rehearsal-reminders.yml](../../.github/workflows/rehearsal-reminders.yml) —
расписание закомментировано, ручной запуск (`workflow_dispatch`) оставлен.
Дрейфует на 5–20 минут, пропускает запуски под нагрузкой и отключается сам после
60 дней без активности в репозитории. Бесплатен только потому, что репозиторий
публичный.

**Как включить обратно.** Раскомментировать расписание; получаса достаточно —
окна намеренно широкие (0–1 ч для «через час», 12–24 ч для «завтра»), и проверка
раз в тридцать минут ловит каждую репетицию внутри её окна. Резервный при живом
основном стоит поставить раз в пару часов: задвоение безопасно, потому что
каждая отправка заявляется в `native_push_reminders` до отправки, — но за лишние
пробуждения базы мы платим.

## Пуши и сборка

### Expo

Два разных сервиса под одним аккаунтом.

**Expo Push Notification Service** — сервер шлёт пуши не в APNs напрямую, а через
серверы Expo, пакетом `expo-server-sdk`. Бесплатно, ключей в нашем коде не
требует.

> Доставка не отслеживается: тикет Expo означает «принято к отправке», а
> receipts, которые говорят, дошло ли до телефона, мы не запрашиваем.

**EAS Build / Submit** — сборка iOS-бинарника и загрузка в App Store Connect.
Конфиг [eas.json](../eas.json). Профиль `production` готов, но блок
`submit.production` пустой — туда нужны `appleId`, `ascAppId`, `appleTeamId`.

### Apple Developer Program / App Store Connect

| | |
|---|---|
| Переменная на сервере | `APPLE_CLIENT_ID` (= bundle id `com.rehearsal.app`) |
| Читается в | [server/utils/oauthVerification.js](../server/utils/oauthVerification.js) |
| Цена | $99 / год |

Что на нём держится: App ID `com.rehearsal.app` с capability Push Notifications,
ключ APNs (создан через `eas credentials`), сертификаты подписи, TestFlight,
запись приложения, и Sign in with Apple — обязательный по Guideline 4.8, раз на
экране входа есть Google.

**Нужна только `APPLE_CLIENT_ID`.** `APPLE_TEAM_ID`, `APPLE_KEY_ID` и
`APPLE_PRIVATE_KEY` понадобились бы для server-to-server обмена, которого у нас
нет: `apple-signin-auth` сам забирает публичные ключи Apple.

### Google Cloud Console — вход через Google

Три OAuth client ID: iOS, Android, Web. Токен проверяется на сервере через
`google-auth-library`, с проверкой audience и issuer.

**Идентификаторы лежат в коде**, в
[server/constants/googleClients.js](../server/constants/googleClients.js), а не
только в переменных. Это не секреты — они и так уезжают в `app.json` вместе со
сборкой. Так сделано после отказа входа: в боевых переменных лежали устаревшие
значения. Переменные `GOOGLE_CLIENT_ID_IOS` / `_ANDROID` / `_WEB` теперь
**дополняют** список, а не заменяют его.

## Почта

### Resend — исходящие письма. Ещё не настроен

| | |
|---|---|
| Переменные | `RESEND_API_KEY`, `MAIL_FROM` |
| Читается в | [server/utils/mailer.js](../server/utils/mailer.js) |
| Без ключа | `sendMail` молча возвращает `false`, ничего не роняя |

Нужен для подтверждения почты (закрывает находку аудита A01 — захват аккаунта по
чужому адресу) и для восстановления пароля.

**Осталось сделать:** завести аккаунт, добавить DNS-записи DKIM и расширить SPF,
положить `RESEND_API_KEY` в Vercel.

### ImprovMX — входящая почта

Пересылка `support@rehearsly.me` на личный ящик. Этот адрес указан на страницах
поддержки сайта. **Только приём** — отправлять программно через него нельзя,
ровно поэтому появился Resend. Держится на MX-записях домена.

## Админка

Не внешний сервис, но со своими доступами: `/admin` на том же Vercel.

| Переменная | Назначение |
|---|---|
| `ADMIN_PASSWORD_HASH` | bcrypt-хеш пароля — рекомендуемый способ |
| `ADMIN_PASSWORD` | открытый пароль, устаревший запасной вариант |
| `ADMIN_JWT_SECRET` | подпись токена сессии; при отсутствии берётся `JWT_SECRET` |

## Полный список переменных

| Переменная | Сервис | Без неё |
|---|---|---|
| `DATABASE_URL` / `POSTGRES_URL` | PostgreSQL | DB API503; SQLite fallback отсутствует |
| `SERVER_ENV_FILE` | необязательный локальный файл | используется только process environment; автоматического поиска `.env` нет |
| `JWT_SECRET` | — | обязателен в production, сервер не стартует |
| `CRON_SECRET` | триггеры напоминаний | эндпоинт отвечает 503 |
| `BASE_URL` | Vercel | ломаются инвайт-ссылки и CORS |
| `APPLE_CLIENT_ID` | Apple | Apple login отключён guard; OPS-IA01 production-проверка остаётся NOT_RUN |
| `GOOGLE_CLIENT_ID_IOS` / `_ANDROID` / `_WEB` | Google | ничего: список есть в коде |
| `RESEND_API_KEY`, `MAIL_FROM` | Resend | письма молча не уходят |
| `ADMIN_PASSWORD_HASH` / `ADMIN_PASSWORD` | админка | не войти в `/admin` |
| `ADMIN_JWT_SECRET` | админка | берётся `JWT_SECRET` |
| `HOST` | — | `0.0.0.0` нужен, чтобы зайти с физического устройства |
| `PORT` | — | по умолчанию 3001 |
| `EXPO_PUBLIC_API_URL` | клиент | адрес API определяется автоматически |

## Что проверить, если что-то не работает

| Симптом | Куда смотреть |
|---|---|
| Запросы возвращают ошибки, вход не проходит | Neon: не выбран ли лимит compute |
| Напоминания не приходят | оба триггера выключены с 2026-09-12 — это ожидаемо |
| Вход через Google отказывает | client ID в `constants/googleClients.js` против Google Console |
| Инвайт-ссылка открывает сайт, а не приложение | `BASE_URL` и `apple-app-site-association` на том же origin |
| Письма не приходят | `RESEND_API_KEY` в Vercel, DKIM и SPF в DNS |
| Пуш принят, но не дошёл | доставка не отслеживается — receipts Expo не запрашиваются |
